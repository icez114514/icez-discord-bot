# 水晶賭場開發規格與驗收清單

狀態：規劃完成，尚未實作正式 Bot。此文件是已確認決策的交付快照；後续變更以決策議題的最新 resolution 為準。

決策地圖：https://github.com/icez114514/icez-discord-bot/issues/1
原型：同分支 docs/prototypes/crystal-casino.html，下載後直接以瀏覽器開啟。

重要整合提示：此分支僅保存文件與原型，基準 commit 不包含主工作區所有尚未提交的水晶功能。開發時須以現有 F:/tools/Discord Bot 水晶實作為整合對象，先妥善保存那些變更；不可把此原型分支誤當完整最新 Bot。原型使用固定結果／記憶體資料，不可直接拿其遊戲邏輯、權限示範或恢復模擬上線。

## 範圍與來源

首版 21 點與 18 豆仔，各自對系統莊家；無抽水、無產品下注上限、跨遊戲每人一局。既有每日簽到與排行榜繼續運作。
18 豆仔規則來源：https://github.com/mxicat/mei-bot/blob/master/gamble.js 。雙方各擲 3 顆 1–6 骰子；豹子依數字大小 > 456 > 對子以外單顆點數 > 123 > 其他散骰；同級比三顆總和，再同則平手；散骰不重擲。普通勝利淨賺下注額、輸扣下注額、平手不增減。明確不沿用原程式賭博稅、固定帳號／頻道及 JSON 存檔。

## 開發整合次序

1. 檢查現有 CrystalStore／PostgreSQL 與功能註冊，先實作牌局、偏好、金流及單局唯一性；既有帳戶餘額不重置。
2. 實作可用固定牌序／骰序驗證的純遊戲判定，正式隨機來源獨立，不沿用示範固定結果。
3. 串接原子扣款、加倍、單次結算／退款與重啟恢復，再接 Discord UI；UI 失敗不回滾已完成金流或重開結果。
4. 實作公開且限主人操作的面板、私人查詢與管理附加訊息。最後加入素材合成與按牌局版本順序更新。
5. 執行以下及各決策所附驗收，使用測試伺服器確認手機／桌面、重啟與權限行為。

## 資料遷移與維運驗收

- 以可重入遷移新增牌局、操作／金流與偏好儲存；保留所有既有水晶餘額及簽到資料，不拿參考專案的 JSON 覆蓋現有資料庫。
- 遷移前取得資料庫備份；在隔離副本驗證遷移與備份還原可查回帳戶、未完局、期限及流水。這是上線檢查要求，不是已具備備份的宣稱。
- 部署切換時暫停新開局並妥善處理在途請求；復原程式遇到已提交操作不得重複執行。回退程式時保留新資料，不以刪表或清帳處理。
- 已結算統計可由流水核對／重算，作廢退款另列。保留期間不自動清除；資料量增加時以索引、分頁與封存設計維持可查帳，不偷偷改成到期刪除。
- 以並行開局／簽到、重送結算、扣款提交前後中斷、Discord 發送失敗、重啟跨逾時點驗證資金一致性。
- 量測合圖耗時、上傳／訊息更新延遲及併發時事件迴圈反應，記錄條件與結果，不宣稱未量測的承載人數。遵循 Discord 動態限流與退避。
- 真實圖片未提供前使用明確佔位素材；上線前選定荷官、牌面、牌背與骰子素材並確認可使用。不要求 AI 生成，不影響以佔位素材完成邏輯開發。

## 水晶賭場：莊家資金與原子結算如何定義

來源：https://github.com/icez114514/icez-discord-bot/issues/2#issuecomment-5556933432

## Resolution

使用者已確認系統派彩／回收、开局即扣下注及下列保護機制，並要求各遊戲分別統計莊家／玩家勝負與總金額、持久保存遊戲紀錄。本決策為開發規格，功能尚未實作或測試。

### 資金與結算契約

- 莊家是系統派彩／回收方，不設需儲值的有限資金帳戶。莊家淨盈虧為統計，不限制賠付；首版不抽水。
- 實際下注 = 基本金額 × 倍率。沿用最低 2、偶數、倍率為正整數，不設產品下注上限，仍須足夠可用餘額。全部金額採精確整數運算；不能以浮點或靜默截斷取代檢查。
- 開局成功時立即扣除實際下注。扣款、可恢復牌局資料與流水必須同一資料庫交易成功；任一步失敗，全部回滾。沒有水晶帳戶或餘額不足時不得開局，不由賭場額外發放初始水晶。
- 加倍時再扣原下注額，並與牌局狀態／操作流水一起提交；餘額不足則拒絕，原牌局繼續。
- 令 B 為該局累計已扣下注（含加倍）。一般勝利返還 2B、平手返還 B、失敗返還 0；天然 21 點勝利返還原下注的 5/2，其中含本金。天然及加倍何時可用由牌局細則議題決定。
- 每人以現有跨伺服器 user_id 為範圍，兩款遊戲合計至多一個未完成局。並行開局、加倍、簽到須在資料庫正確協調，不得覆蓋餘額。
- 每個開局／操作／結算有可去重識別；相同操作重送與多次恢復不得重複扣款或派彩。最終狀態、返還及對應流水一併提交；統計可由已提交紀錄重算，或以同一交易維護，不能重複累加。

### 異常與恢復

- 扣款成功但 Discord 發送或編輯失敗：保留原局，不另開或重扣，可由 /賭場 找回。
- Bot 重啟：恢復原局與原期限；已逾時依既定 120 秒自動停牌、莊家結算，不因重啟改變牌／骰結果。
- 僅確實無法恢復的異常局，退回全部已扣下注（含加倍），一次性標記作廢並記錄原因。一般逾時、畫面失敗或玩家斷線不構成作廢理由。
- 已完成的局不能再自動退款；若故障後無法確認是否已提交，先依牌局／流水查證，不能盲目重送派彩或退款。

### 勝負與金額統計

- 每款遊戲分別提供：每位玩家的勝／負／平手局數，以及對應莊家的整體勝／負／平手局數。莊家勝即玩家負，反之亦然。
- 記錄累計下注、累計返還（含本金）、淨盈虧。正常已結算局玩家淨盈虧 = 返還 - 下注；莊家淨盈虧為玩家合計淨盈虧的相反數。
- 開局與加倍在流水均有紀錄；正式勝負／盈虧統計只計正常已結算局。未完成局、異常作廢局與退款另列，避免把退款當成贏局或虛增正常下注量。
- 莊家金額可核對玩家合計：下注為莊家收取額、返還為莊家支出額，淨額為兩者差額。

### 持久遊戲紀錄

資料庫保存牌局 ID、玩家、遊戲、基本下注／倍率／實際下注、牌或骰結果及可恢復狀態、有效操作及時間、加倍、正常結算／退款原因、各次水晶異動（含前後餘額及流水識別）。未完成局暗牌不得向玩家公開。

紀錄保留期間、查詢權限與管理查帳入口仍需另案確認；不將應用程式終端 log 視為可靠金流紀錄。

### 必要驗收情境

- 初始 1000、下注 100，開局 900；一般贏最終 1100、平手 1000、輸 900。
- 初始 1000、下注 10，天然勝利返還 25，最終 1015。
- 初始 1000、下注 100 再加倍 100，可用餘額 800；一般贏返還 400 最終 1200，平手返還 200 最終 1000，輸最終 800。
- 開局交易中途失敗：餘額與未完成局均不改變；並行兩次開局至多一局成功。
- 同一加倍或結算重送：金額與局數只變一次；派彩提交後重啟不能再次派彩。
- Discord 發送失敗仍能恢復原局；重啟跨過期限後自動結算。
- 不可恢復局退回含加倍的全部本金，重複恢復不再次退款，不計正常勝負。
- 對每局與每款遊戲核對流水、返還、淨盈虧與莊家相反數，並確認簽到並行不遺失任何金額。

## 水晶賭場：21 點發牌與加倍邊界如何判定

來源：https://github.com/icez114514/icez-discord-bot/issues/3#issuecomment-5556961674

## Resolution

使用者已確認以下完整細則。本議題只固定開發規格及預期結果，尚未實作或執行測試。

### 發牌與計點

- 每局使用一副標準 52 張牌，無鬼牌，重新洗牌；玩家與莊家共用該副牌，抽出的牌不放回。
- 2–10 按牌面，J／Q／K 算 10。A 可算 1 或 11，以不爆牌的最大總點數為準；所有 A 都算 1 仍超過 21 即爆牌。
- 初始雙方各兩張，莊家一明一暗。牌面與剩餘牌組必須能隨原局恢復，不因重啟重新抽牌。

### 天然 21 點與暗牌

- 天然僅指初始兩張 A 加 10／J／Q／K。三張以上湊出 21 是一般 21，非天然。
- 起手先檢查雙方天然。雙方天然平手；只有玩家天然則玩家勝，淨賠 3:2；只有莊家天然則玩家負。任一方天然時立即揭牌結算，不進入要牌／加倍階段。
- 其餘情況，莊家暗牌在玩家停牌後揭開，再執行莊家回合。玩家補到 21 或加倍補牌未爆牌時，視為自動停牌。
- 玩家爆牌立即判負，不再讓莊家補牌。結束畫面是否展示莊家未動用暗牌屬面板呈現，不影響結果；未完成局不得洩漏暗牌。

### 操作與勝負

- 要牌：抽一張；爆牌立即負，達 21 自動停牌，其餘可繼續要牌或停牌。
- 加倍：僅玩家首兩張、尚未要牌時可用，不限點數且需足夠餘額；再扣與原下注相同金額，只補一張後自動停牌，爆牌則立即負。不能再次加倍或加倍後要牌。
- 停牌後莊家不足 17 必須補牌，17 以上停牌，包含軟 17（例如 A+6）。
- 玩家未爆牌而莊家爆牌則玩家勝；雙方未爆牌比較點數，高者勝、相同平手。
- 沿用資金結算決策：一般勝利淨賠 1:1、天然淨賠 3:2、平手退回下注、無抽水。加倍後以累計下注結算；天然階段已結束，不會產生加倍後天然。
- 首版不提供分牌與保險。

### 120 秒未操作期限

- 從輪到玩家操作時起算；有效要牌後如仍輪到玩家，重新計時 120 秒。
- 無效操作、重複 interaction、開啟面板與其他人的點擊均不延長期限。
- 到期自動停牌並由莊家完成結算；Bot 重啟沿用原期限，不重新給 120 秒。
- 逾時與玩家操作競爭時，只能有一個有效狀態轉移，不能雙抽牌或雙結算。

### 判定驗收範例

下列為可直接轉成固定牌序測試的預期行為，並非已通過測試的宣稱。

| 情境 | 預期 |
| --- | --- |
| 玩家 A+K，莊家 A+Q | 雙方天然，立即平手 |
| 玩家 A+10，莊家 10+9 | 立即玩家天然勝利；下注 10 返還 25，淨賺 15 |
| 玩家 10+9，莊家 A+K | 立即玩家負；不提供加倍或要牌 |
| 玩家 7+7，要到 7；莊家 10+8 | 玩家一般 21 自動停牌，普通勝利 1:1，非天然 3:2 |
| 玩家 A+6，要到 10 | 玩家為硬 17，未爆牌，可繼續操作 |
| 玩家 A+A+9 | 21，自動停牌 |
| 玩家 10+8 停牌；莊家 A+6 | 莊家軟 17 停牌，玩家勝 |
| 玩家 10+8 停牌；莊家 10+6，補到 2 | 莊家必須補牌，18 平手 |

## 水晶賭場：遊戲紀錄保留與查詢權限如何定義

來源：https://github.com/icez114514/icez-discord-bot/issues/5#issuecomment-5556983872

## Resolution

使用者已確認以下整組設定。這是開發規格，尚未實作或執行測試。

### 保存範圍與期限

首版牌局、操作、金流及統計均不自動刪除，不設自動到期清除工作。這是資料保留政策，不代表資料庫已具備備份或災難復原；相關維運驗收仍須在交付規格中明列。

### 玩家查詢

玩家可查看自己的歷史牌局，以及各遊戲勝／負／平手、累計下注、返還及淨盈虧。查詢面板僅本人可見；玩家身分以已確認的跨伺服器水晶帳戶 user_id 對應。不得透過其他玩家 ID、牌局 ID 或轉傳按鈕取得他人明細。

### 公開莊家統計

公開各遊戲莊家總勝／負／平手、累計收取金額、累計返還及淨盈虧。只提供彙總，不公開其他玩家明細。金額與異常退款統計口徑沿用已結案的資金決策，不把返還本金視為獲利。

### 管理查帳

只有 Bot 擁有者或明確指定的查帳人員可以依玩家或牌局編號查閱完整紀錄。一般伺服器管理員不因其 Discord 管理權限而自動獲得跨伺服器查帳權限。

指定人員須有明確授權資料；不將顯示名稱、一般身分組名稱或可猜測的牌局編號當作授權。查詢指令及每次按鈕／翻頁／Modal 提交均須驗證當下權限，撤銷授權後舊面板也不可繼續查閱。具體設定入口與面板布局由面板決策承接。

### 未完成牌局

查詢介面不顯示未完成局的莊家暗牌或剩餘牌組，此限制也適用管理查帳介面。可恢復狀態仍保存在資料庫；恢復所需內部資料不等於介面可公開內容。

### 驗收情境

- 玩家 A 可查自己跨伺服器的已完成牌局與遊戲統計；玩家 B 使用 A 的牌局 ID 或按鈕不能取得明細。
- 玩家查詢回覆僅本人可見；公開莊家統計只含各遊戲彙總。
- Bot 擁有者與明確授權查帳人員可依玩家／牌局 ID 查帳；僅有伺服器管理員權限者被拒絕。
- 撤銷查帳授權後，已開啟面板的翻頁及後續操作也須被拒絕。
- 未完成局在玩家與管理查詢畫面中均無暗牌及剩餘牌組。
- 牌局與金流沒有自動到期刪除；重啟後仍能查詢已保存資料。彙總可與牌局／金流核對，異常作廢不計正常勝負。

### 大廳、設定與可見性

- /賭場 在無進行中牌局時顯示公開大廳：荷官圖片、21 點／18 豆仔遊戲按鈕，以及我的紀錄／莊家統計入口。這些入口只在大廳。
- 有進行中牌局時 /賭場 優先恢復原局；同一玩家跨遊戲與伺服器至多一個未完成局。新面板接手後舊操作不可再生效。
- 大廳、下注、遊戲及結算公開可見，但每個按鈕與 Modal 提交只接受面板主人。其他人點擊回覆私人拒絕訊息，不修改公開面板或原局。
- 私人紀錄與查帳以獨立私人回覆顯示，不把公開原訊息轉成私人，也不向公眾發送私人資料。公開遊戲画面意味當局下注、可用餘額與結果會供觀眾看見；歷史明細仍受既定查詢權限限制。
- 伺服器內可使用指令的頻道皆可使用賭場；不複製參考專案的固定頻道 ID。
- 選遊戲後進入下注設定，帶入共用偏好。基本下注按鈕 10／50／100／500／自訂，倍率按鈕 ×1／×2／×5／×10／自訂。
- 基本金額至少 2 且為偶數，倍率正整數；實際下注為兩者相乘。不設產品上限，餘額不足禁止開局。自訂輸入接受十進位整數，不以浮點近似大額水晶。
- 金額與倍率跨遊戲、跨伺服器共用；有效設定立即保存，餘額不足仍可保存偏好。切換固定值保留上次自訂值，Modal 預填上次自訂值。

### 遊戲與結算操作

- 21 點提供要牌／停牌／加倍；進行中返回不可用，後端仍需檢查牌局狀態，不僅依賴 disabled 外觀。
- 18 豆仔開局即擲骰並結算；每次有效開局只有一組結果。
- 結算僅三個按鈕：再來一局、修改下注、返回大廳。
- 再來一局：沿用上一局開局的基本下注與倍率，直接同款開局扣款；不沿用 21 點途中加倍的累計下注。若餘額不足則不可再開。每個已結算面板只能觸發一次後續開局，包含立即結算的 18 豆仔，以免連點產生多局。
- 修改下注：帶入現有偏好回設定，不扣款。
- 返回大廳：僅無進行中牌局才允許；不得與並行開局競爭而繞過檢查，不會取消或退款原局。
- 關閉／遺失訊息不取消原局；恢復沿用資料與期限。互動過期時提示重新 /賭場，不能改變牌局结果。

### 圖片與配色

- 遊戲以牌桌圖片為主，放大置中的牌面／骰子，少量文字保留點數、下注、返還含本金、淨盈虧、餘額及期限。
- 正式圖片由預製荷官、背景、牌面、牌背、骰子素材組合，不用 AI 每回合生成。有效牌局變動後更新同一訊息，倒數不每秒重畫，莊家回合可直接顯示最終結果。
- 素材預載快取，圖片合成避免阻塞事件迴圈，圖像更新按牌局版本排序。圖片失敗時保留文字牌面／點數與必要金額，不重扣、不重新擲骰、不改變結算。未揭露暗牌不可先傳給客戶端再靠遮罩隱藏。
- 原生 Primary 紫藍：要牌／加倍／修改下注／自訂輸入及選取值；Success 綠：開局／再來一局；Danger 紅：停牌；Secondary 灰：返回／查詢。兩款遊戲入口紫藍／綠。實際顏色依 Discord 主題，不能任意自訂色碼。
- 原型為線框及固定結果；正式荷官與牌面美術尚待提供，不影響開發規格可交付。沒有素材時保留佔位圖或文字，不使用未經選定的遠端素材。

### 管理入口

- 不註冊 /賭場查帳。
- 授權管理員開啟大廳時，另附一則 ephemeral 私人訊息，提供管理查帳按鈕；這是同一流程中的私人附加訊息，非公开大廳內依觀看者隱藏按鈕。
- 管理員沿用 Bot 擁有者／設定中明確指定的查帳使用者 ID，一般 Discord 管理員不自動獲得跨伺服器查帳權。
- 管理按鈕開啟玩家／牌局編號查詢輸入，結果與分頁均私人顯示，每次查詢／翻頁驗證當下授權。查帳顯示下注、返還／退款、淨盈虧及操作流水；未完局暗牌與剩餘牌組不顯示。

### 面板驗收清單

- 新玩家進大廳看到荷官圖位置及遊戲列表，未選遊戲前不出現下注操作。
- 選遊戲、修改設定、取消 Modal 與返回不扣款；有效自訂值保存，非法值不改設定。
- 開局与再來一局扣款一次；21 點加倍後再來一局仍用原始基本下注×倍率。
- 他人點擊、舊按鈕、重送 interaction、並行跨伺服器開局均不產生額外扣款或牌局。
- 有未完局不可返回／切換，重新 /賭場 恢復相同牌局及期限。
- 管理入口只出現在授權者的私人附加訊息；撤銷後舊入口與翻頁被拒絕；不出現獨立查帳指令。
- 我的紀錄不洩漏給觀眾；莊家統計只含彙總；觀眾可見遊戲但不能代為操作。
- 文字與圖一致，暗牌不洩漏；更新失敗、亂序及速率限制不影響結算，失敗時有文字牌面回退。
- 桌面與手機確認圖片、金額、按鈕可讀且不超過 Discord 元件限制。
