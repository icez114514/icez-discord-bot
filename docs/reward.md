# reward 管理發獎

直接在伺服器文字頻道輸入，不加前綴、不使用 slash command：

- `reward @成員 100`：給指定成員 100 水晶（實際訊息使用 Discord 成員提及）。
- `reward all 100`：給所有符合資格的既有帳戶各 100 水晶。

只允許角色 ID `433683517235265537` 或 `439412731632680960`；Discord 管理員權限本身不放行。
每次從 Discord REST 驗證操作者角色，寫入前再次確認。私訊、Bot、webhook 忽略。
不限制頻道名稱。數量只接受十進位正整數，不接受小數、負數、科學記號或混雜文字。
不新增金額上限；超長數量在回覆中簡寫，帳務保存完整精確數值。

全體對象須已有水晶帳戶、仍在目前伺服器，且至少一個獨立顯示角色的位置達到
`LV.10 女武神．戰車`。採角色位置而非等級名稱數字；符合條件的 Bot 不額外排除。
每批最多 4 個成員查詢同時執行。缺少門檻角色或成員查詢失敗不發放；
只有 Discord 10007（Unknown Member）才當作已離開並跳過。資格以寫入前查詢的快照為準。

單人允許發給自己；無帳戶時由零建立，不送新人額外水晶，也不改簽到日期。
取消原版特殊角色公告與操作者 +20 機制。成功只在原頻道回覆人數與每人金額。

## 流水與防重複

`reward_operations` 保存訊息 ID、操作者、伺服器、頻道、模式、每人金額、人數與時間；
`reward_entries` 保存每位收款人的金額、前後餘額與時間。資料與帳戶更新在同一交易提交。
同訊息 ID 只發放一次；不同訊息是不同發獎，請勿因回覆失敗另發新訊息重試。
提交結果不明時僅回查流水，不自動重做加款。發獎流水不列入賭場輸贏或營收。

管理員可唯讀查詢 `reward_operations` 的 `message_id`，並連結 `reward_entries`
核對實際收款人與金額；目前不新增 Discord 查帳指令或面板。
計時記錄在 `logs/latency.log`，一般 console 不輸出計時。

## 部署

更新後執行 `python -m database init`，建立兩張新表；可重複執行且不重算既有餘額。
`python -m database check` 會檢查發獎表，Bot 啟動也會檢查；`bot.py --check` 仍不連線。
完成後重啟 Bot。只需要既有 Message Content Intent，無須完整成員快取或新增 Members Intent。
回退程式時保留流水表，不回退已入帳水晶。
