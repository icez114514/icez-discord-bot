狀態：Draft／只規劃，尚未實作。日期：2026-09-16。

本文件依使用者要求暫存於本機，採 wayfinder 的目的、已知決策、待決問題結構；不是已發布的 GitHub map 或已核准的實作計畫。原始四項需求及使用者後續同意的七項優化已納入範圍，加上第二輪選定的重連狀態提示，共十二項；第二輪其餘四項明確不採用。

## Destination

讓玩家看懂下注、收池、派彩與勝者，能切換自己的桌上籌碼顯示，並補齊牌局音效，以及結算明細、行動標籤、自訂下注、分類音量、手牌回放、易讀牌面、安全預選與重連狀態提示。先形成可討論與驗收的規格，不改遊戲程式、不部署、不更動帳務或牌局規則。

## 已確認需求與建議規格

### 1. 籌碼出去、收回、分配動畫

視覺順序：玩家桌上籌碼 → 座位前投注區 → 中央底池 → 各收款玩家。

- 盲注、跟注、下注、加注與全下：以本次新增投入額呈現籌碼移動，不能把累計投注重播為新增投入。
- 下注輪結束：各投注區籌碼收進中央；收池不代表底池金額再增加一次。目前總底池本來就包含該輪投入。
- 結算：依主池／邊池／分池結果，籌碼從對應底池移向玩家；同一人可領多個池。
- 未跟注金額退回：明確顯示「退回 X」，不能以勝利效果取代。作廢退款同樣不代表贏牌。
- 連續快照跳過中間狀態時，以可靠事件或結算摘要補足可確認的順序；沒有證據時只呈現最終狀態，不猜測中間動作。
- 建議每段 200–450 ms，以少量代表籌碼而非每枚一個節點；視覺佇列需可合併或加速，不能延遲下一位行動或改變倒數。
- 動畫依座位元素實際位置定位，適用自己的座位旋轉、手機、桌機與視窗縮放；不遮蓋操作按鈕。
- 伺服器已確認金額立即成為權威值；移動籌碼只是呈現，動畫完成不得觸發真正入帳。

### 2. 收款與頭像 WIN 動畫

- 籌碼抵達贏家時，座位有短暫入帳亮光或數字浮現，頭像上方／覆蓋層顯示 `WIN`。
- `WIN` 的建議定義：贏得至少一個實際底池，不等同整手淨獲利。分池或贏小邊池但整手虧損，仍可能是該池贏家。
- 應使用伺服器的底池勝者與退款資訊判斷，不用 `payouts > 0` 或桌上餘額增加直接判勝。
- 建議顯示「派彩 X」；退款另列「退回 Y」。若日後顯示淨損益，需另以整手投入計算並標為「本手淨變動」，不能把派彩當成淨賺。
- 多位勝者均有 WIN；同一人領多池可分段收到籌碼，但勝利音與主慶祝效果每手每人只觸發一次。
- 建議 WIN 保留約 1–1.5 秒，或至下一手開始前；新手開始必須清除，不能標到重新入座的另一個玩家。
- 初次載入／重連至已結算牌局可保留靜態結果，但不補播過期慶祝。
- 減少動態效果時，以 WIN 文字、外框及入帳數字替代飛行、縮放與閃動。

### 3. 點自己的籌碼切換實際額／BB

- 點擊自己頭像旁的桌上籌碼數字：`12,350` ⇄ `123.5 BB`（大盲 100 範例）；不需要開設定視窗。
- 按鈕需支援鍵盤、觸控與可讀標籤，切換不送出下注或其他金錢指令。
- 首版只影響自己的桌上籌碼；其他玩家、底池、下注輸入是否同步切換列為待決選項。
- BB 為桌上籌碼除以該手／該桌大盲。需以可靠桌規資料取得大盲，不能只依目前標題的 `50 / 100` 硬編碼。
- 建議最多兩位小數、去尾零，非整除且需四捨五入時顯示約值，另提供精確整數額；保持 BigInt／定點計算，不將大額籌碼直接轉 Number。
- BB 缺失或不合法時回退實際額；不得顯示 NaN／Infinity。
- 建議記住同裝置、分帳號的顯示偏好，儲存失敗仍可在本次會話切換；跨裝置同步可另決定。

### 4. 補齊音效

先建立事件覆蓋表，再決定是否需要新素材。重用現有授權清楚的本地音效，音效失敗不能阻塞操作。

| 事件 | 建議音效與規則 |
| --- | --- |
| 新手發底牌、翻牌／轉牌／河牌 | 發牌聲，連續發牌可合併；不能因此漏播同次結算 |
| 盲注、下注、跟注、加注、全下投入 | 籌碼聲，依伺服器確認動作觸發；滑桿預覽不能冒充已下注 |
| 過牌、棄牌 | 可辨識且輕量的不同聲音；需明確動作依據 |
| 每輪收池 | 一次收籌碼聲，避免六個座位同時疊音 |
| 派彩、贏家收款 | 配合抵達時刻；結算主聲每手一次，多池避免反覆慶祝 |
| 未跟注退回、作廢退款 | 中性退款提示，不播放 WIN 聲 |
| 輪到自己、最後五秒、開始使用補時池 | 保留現有提示；優先於裝飾音，不能被併發上限擠掉 |
| 操作確認、拒絕、連線中斷／恢復、補碼完成 | 建議短提示且必須有文字；斷線抖動需去重／節流 |

- 將「快照不同」與「明確事件發生」分開；同次包含投入、翻牌及結算時，各必要提示可排序／合併，不能只靠 else-if 播一項。
- 事件去重需跨 HTTP 回覆、WS 推播、React 重繪及頭像資料更新；建議使用 hand_id＋伺服器事件序號＋事件類型，具體資料契約待定。
- 保留互動解鎖、靜音持久化、背景不播、重連不補播舊音效等既有行為。
- 現有播放限制包含載入逾 600 ms 丟棄、同時最多四個聲源；需檢查首次載入及密集事件，判斷哪些丟棄合理、哪些導致關鍵提示缺漏。
- 首次互動後可預載常用素材；狀態型提示應可診斷為 muted／locked／hidden／load failed／deduplicated／played，不能把所有靜音誤判為錯誤。
- 分組音量、試聽與獨立提示開關已納入第 8 項；具體分組與預設音量仍為建議值。

### 5. 主池／邊池結算明細（已納入）

- 結算摘要可展開主池、各邊池金額、得主與每人實領；退款另列，合計必須吻合伺服器結算。
- 分池與奇數籌碼以實際分配結果顯示，不由前端再判勝或重分配。
- 明細與動畫共用同一份結算資料；手機可展開查看，不能阻擋下一手操作。
- 驗收：一人多池、多人平分、退款與派彩並存時，所有明細加總正確，退款者不誤標 WIN。

### 6. 玩家行動標籤（已納入）

- 座位顯示過牌、跟注、下注、加注、棄牌、全下；附金額時區分「本次投入」與「加注至」。
- 以已確認公開事件觸發，不以餘額差猜測行動；與籌碼動畫及音效共用事件去重。
- 已有棄牌、全下、正在行動等持續狀態需保留；短暫行動標籤不能覆蓋離線或坐出資訊。
- 驗收：同一玩家連續行動、街次切換、重送與重連不產生重複或錯誤標籤；標籤不沿用至下一手。

### 7. 自訂下注快捷按鈕（已納入）

- 翻牌前使用可設定 BB 倍數，翻牌後使用可設定底池比例；建議沿用五個按鈕的位置。
- 按快捷按鈕只填入下注草稿，仍由玩家按下注確認；此處「快捷」不等於鍵盤立即送出指令。
- 底池比例沿用跟注後底池計算與 raise-to 語意；BB 按鈕同樣表示本輪加注至多少 BB。
- 超出合法範圍時夾至伺服器上下限並顯示實際額；若結果是全下，沿用全下確認。
- 個人設定不更動牌桌版本或帳務；預設值、上下限與跨裝置同步方式仍待定。
- 驗收：盲注投入、短碼全下、未重開加注權、極大額與小數 BB 換算不送出不合法數值。

### 8. 分類音量與試聽（已納入）

- 建議分為回合／倒數提醒、牌局／籌碼、結算／勝利、介面提示；另保留總靜音與總音量。
- 每組可調音量與試聽；試聽須經使用者操作，不解除總靜音，不發出遊戲指令。
- 偏好可保存，儲存失敗不阻塞牌局；重要提示採播放優先序但不越過使用者的關閉設定。
- 驗收：各組獨立、總靜音有效、音量為零無聲、重新載入偏好一致，背景與重連不補播。

### 9. 上一手摘要與完整手牌回放（已納入）

- 先提供上一手摘要，再提供逐步前後、播放／暫停、跳街及最終結算；兩階段均屬本次已納入範圍。
- 來源為伺服器保存的已結束手牌，不能把目前 80 筆連線紀錄當完整歷史。
- 只提供本人參與且有權查看的資料；可見底牌限自己的牌與該手已合法公開的牌，棄牌者未公開底牌不可因結束而揭露。
- 回放與即時桌況分開；回放中的按鈕不送牌局操作，即時輪到自己時提供返回牌桌提示。
- 保存期限、可查手數、篩選方式與是否匯出仍待定；不自動擴大為公開分享功能。
- 驗收：斷線期間仍有完整合法歷史，未參與者拒絕存取，已離桌者依權限可看自己的手牌；回放不播成即時入帳或重複派彩。

### 10. 四色牌與大字模式（已納入）

- 提供可選四色花色及大字牌面，原本牌色與三主題保留為預設。
- 使用數字、花色符號及顏色共同辨識；不能只靠顏色；大字模式同時適用底牌與公共牌。
- 先改善牌面與關鍵數字可讀性，不擅自重排所有桌面操作。
- 驗收：320／390px、桌機、各主題與放大文字下不遮住底池、籌碼、倒數及行動按鈕。

### 11. 安全預選操作（已納入）

- 建議包含「可過牌就過牌，否則取消」及「跟注目前顯示金額」；預設未啟用，玩家每次自行勾選，且可取消。
- 預選只對目前這一手、這一街的下一次本人行動有效；綁定玩家、桌、手、街、選擇時的確切跟注額與控制端。
- 正常其他玩家行動會推進全桌 turn，不能僅因 turn 遞增就讓所有預選失效；輪到本人時重新核對手／街、金額、合法動作與控制權，再建立當下有效指令。
- 跟注額不同、街次變更、新手、離桌／坐出、斷線、控制權轉移或本人已行動，均清除預選；不支援「跟注任何金額」。
- 若跟注變成全下，不能繞過既有全下確認；建議取消自動執行，交回一般行動面板。
- 不預選加注或全下；不以客戶端過期狀態直接執行，伺服器仍檢查回合、版本及期限。
- 驗收：正常輪轉可執行一次；加注後金額改變、同手下一街、重連與跨視窗不誤送；相同意圖不重複扣碼。

### 12. 重連狀態提示（已納入）

- 以桌面上可見、非阻擋的狀態區顯示「連線恢復中」「同步桌況中」「已同步」；不能只因 WebSocket 開啟就宣稱同步完成。
- 連線狀態、控制權與指令結果分開表達：連線恢復後，仍可能是「結果待確認」或「目前由另一視窗操作」。
- 有尚未確認的操作時，保留既有相同 command_id 與原始內容重送流程；不能以新 ID 重做下注，也不能把已同步桌況當作原指令已成功的證據。
- 未取得最新權威桌況、沒有操作控制權或指令結果仍未明時，維持相應操作鎖定並說明原因；不得允許過期回合指令。
- 恢復後顯示目前輪到誰及伺服器期限所對應的剩餘時間；清除過期預選，不補播斷線期間的舊籌碼動畫或音效。
- 登入已撤銷則提示重新登入，不能一直顯示恢復中；已離桌、關桌或凍結則顯示實際狀態，不誤報為普通網路問題。
- 提示需可由輔助科技讀取，不只靠顏色；短時間反覆斷線時合併提示，避免重複音效與通知刷屏。
- 此項只改善既有連線／同步／指令狀態的呈現，不新增斷線保護時間、不改補時或結算規則。
- 驗收：斷線後恢復、指令已提交但回覆遺失、重複重送、連上但尚未同步、登入撤銷、另一視窗取得控制權及桌況凍結時，提示與可操作範圍一致且不重複扣碼。

## 驗收情境（後續實作時執行）

1. 一般跟注／加注、多人投入、跨街收池：移動量正確，中央金額不重複計入。
2. 棄牌直接勝出、攤牌、平分、多邊池、奇數籌碼：派彩總量符合伺服器，所有實際勝者顯示 WIN。
3. 僅收退款者不顯示 WIN；同時贏池並收退款者，派彩及退回分開。
4. 同個更新同時完成翻牌與結算：發牌及收款回饋符合序列，不漏結算、不重播。
5. 重複快照、重送相同指令、重連、背景切回及頁面重掛：不重複飛籌碼或慶祝，不改帳務。
6. 大額整數、零籌碼、零頭 BB、切桌及未知大盲：切換正確且不影響下注提交額。
7. 320／390px 手機及 1280×720 桌機、三主題、鍵盤操作及減少動態效果：資訊可讀，按鈕可操作。
8. 靜音、首次解鎖、慢速素材載入、解碼失敗及音效密集時：行動流程正常，重要提示具優先順序。

## 已納入的第一輪平台優化摘要
